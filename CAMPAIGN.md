# Optional poster campaign

## Activate
1. Replace the Apps Script project's Code.gs with backend/Code.gs, then update the existing web-app deployment to a new version. Keep its current URL and permissions.
2. Open the app, log in as admin and choose **Campaign** beside Reminder.
3. Enter heading and invitation, upload a PNG/JPG/WEBP poster (below 7 MB, up to 6000px per side / 20 megapixels).
4. Select Photo or Name, then drag it on the poster. Pinch to resize (or use the corner handle, mouse wheel or +/−). Open Settings for heading, invitation, shape, font, color and ON/OFF. No numeric layout controls are needed.
5. Turn Campaign ON and Save. Reload the app: the normal logo loader covers only the initial campaign settings lookup. An active campaign then appears immediately as a Join Campaign / Continue to App alert, without waiting for saved-session login or app data. Join opens the poster editor directly. Continue (including the editor return button) starts app login/data loading exactly once. OFF or unavailable campaign settings start the app normally. There is no checking screen, early Continue button or artificial delay.

Participants choose a photo, drag and pinch directly on the poster, enter their name and download a PNG. Share Poster opens the device share sheet when file sharing is supported (including WhatsApp if installed). Other browsers download the image for manual attachment. Native sharing depends on HTTPS and browser support. The photo may be zoomed out below the initial frame-fill size; Reset restores its centered crop. The main editor fits the available viewport, while secondary admin settings open in a separate dialog; very small screens and the on-screen keyboard can reduce the preview height. Photos and participant names are composed locally; no registration list is collected. Both visitors and signed-in members can join. Names support Malayalam and English. The template is public via the existing poster upload facility. Test one real download on target mobile devices after deployment; server deployment and Drive image CORS access cannot be verified by unit tests.

Campaign settings use only the POSTER_CAMPAIGN Script Property; payment and member sheets are untouched. Default is OFF. Turn OFF and Save when finished. Keep campaign.html and campaign.js for reuse, or remove the campaign.js script tag and Campaign button from index.html before deleting the two files. No bot changes or additional sheet setup are needed.

Poster templates may have a transparent photo cutout or an opaque reserved area. Transparent cutouts preserve the frame over the photo; opaque photo areas receive the photo on top. Use a transparent PNG when artwork must overlap the photograph. The admin preview uses a PHOTO placeholder and sample Malayalam name.

## Single-line and stacked names
Update backend/Code.gs in Apps Script and deploy a new version to persist the added name layout fields. In Admin → Campaign → Settings choose Single line (original) or Stacked, 2/3/4 automatic lines, and Left/Center/Right alignment. The sample layout uses Stacked, 3 lines, Left. Existing campaigns retain their old name position until the admin selects Name box. Selecting Name box creates a bounded rectangle: drag inside to move, drag any edge or corner to resize, or pinch the whole rectangle. Text shrinks as needed to fit both width and height; preview/download/share clip to the same bounds. Save Campaign persists the rectangle. Preview name is for testing only and is never saved. Participants inherit the admin layout and enter only their name. Old campaigns default to the original single centered line. Preview, PNG download and sharing all use the same rendering.
